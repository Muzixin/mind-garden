# 对话提炼 Skill

## 概述

从当前 LLM 对话中提取可复用的知识(概念定义、方法论、判断框架、问题解答),
直接写入 wiki,不保留原始对话原文。与普通 Ingest 的关键区别:**没有
raw/ 源文件,源是不可回溯的对话上下文**。

## 核心原则

### confidence 固定为"低"

对话提炼的知识源于 LLM 推理而非事实源,不可当权威引用。标注 `confidence: 低`
是对读者的诚实信号。这不妨碍其价值(回忆思路、快速定位),但阻止误用
(当事实引用)。

### 不保留原始对话

只存**提炼后的结构化知识**,不存你问我答的原文。目标:未来翻到这个 wiki
页时,直接看到结论,不需要读对话历史。

### 宁缺毋滥

不是每段对话都值得存。只提炼满足以下至少一项的内容:
- 定义了一个新概念或术语
- 提出了一个可复用的方法论/判断框架
- 解答了一个有通用价值的问题
- 纠正了一个常见误解
- 建立了一个可在未来引用的决策原则

**跳过的内容**:UI 操作记录、临时调试、一次性配置、个人偏好微调、
"帮我改这个变量名"类单次任务。

## 工作流程

### 步骤 1:扫描对话

回顾当前会话,识别所有候选知识片段。每个候选应包括:
- 一个可独立理解的标题
- 一句话概要(让用户快速判断要不要存)
- 建议的存储类型(概念 / 合成)

### 步骤 2:向用户提交候选清单

输出格式:

```
候选知识列表(勾选要保存的):

[ ] <标题 1> — <一句话概要> → wiki/概念/<文件名>.md
[ ] <标题 2> — <一句话概要> → wiki/合成/<文件名>.md
[ ] ...

请告诉我保留哪些(可以用编号,如"保留 1, 3, 5")。
```

**不要自作主张全存。** 用户必须勾选确认。

### 步骤 3:生成 wiki 页面

为每个被勾选的候选生成 wiki 页,遵循 AGENTS.md 约定(frontmatter、命名、
tags、中文):

**概念页**(`wiki/概念/<主题>/<文件名>.md`):
```yaml
---
title: <概念标题>
type: 概念
sources: []
origin: conversation
created: <当前日期>
updated: <当前日期>
confidence: 低
tags: [中文标签, 术语保留英文]
---

# <概念标题>

## 提出背景

[1-2 句说明这个知识是在什么上下文中产生的,不引用对话原文]

## 核心要点

[结构化的知识内容:定义、判断框架、方法论步骤等]

## 适用边界

[什么场景下适用,什么场景下不适用,已知局限]
```

**合成页**(`wiki/合成/<文件名>.md`):
```yaml
---
title: <问题>
type: 合成
sources: []
origin: conversation
created: <当前日期>
updated: <当前日期>
confidence: 低
tags: [中文标签]
---

# <问题>

## 问题

[原始问题的一句话转述]

## 解答

[完整的结构化答案,综合了对话中的多轮推理]

## 推导路径

[简要说明这个答案是怎么得出来的,引用对话中用到的方法论,但不引用原文]

## 适用边界

[已知局限或假设]
```

**如果该概念/主题在 wiki 中尚不存在分类目录,创建对应的 `概念/<主题>/` 目录及其 `_index.md`。**

### 步骤 4:维护索引

- 更新对应 `_index.md`
- 若分类首次出现,在根 `index.md` 添加入口
- 在 `wiki/log.md` 顶部插入记录(倒序):
  ```
  ## [YYYY-MM-DD] extract | <提炼描述>
  Source: conversation
  Created: wiki/概念/<主题>/<文件名>.md, ...
  Updated: wiki/概念/<主题>/_index.md
  Notes: 从对话提炼。<简要注意>
  ```

### 步骤 5:报告

输出创建的页面列表与简要说明,提示:

```
> 提炼完成。建议执行 `git add -A && git commit -m "extract: <标题>" && git push`。
```

## 命名建议

- 概念页:用中文短语,如 `上下文窗口优化策略.md`
- 合成页:用问题式标题,如 `如何评估 RAG 系统的检索质量.md`
- 若 AGENTS.md 不存在,回退到本 skill 默认约定(同 url-ingest 的 schema-snapshot)

## 与 url-ingest skill 的协作

两个 skill 互补:
- **url-ingest**: 外部网页 → raw/ → wiki/(有溯源,confidence 取决于原文)
- **extract-knowledge**: 对话上下文 → wiki/(无 raw,confidence 固定为低)

若同一知识既出现在对话又出现在某篇文章,优先用 url-ingest(可溯源),对话提炼
仅作为补充记录。
